# Личные настройки (UserSettingsView) — левый сайдбар

## Обзор

Страница личных настроек пользователя предоставляет централизованный интерфейс для управления параметрами, которые применяются по умолчанию при создании новых проектов. Структура выполнена в виде двухпанельного макета: левый сайдбар с навигацией и правая области контента с формами.

**Путь:** `/user-settings`  
**Компонент:** `UserSettingsView.vue`  
**Доступ:** Аутентифицированные пользователи

## Левый сайдбар — Разделы (6 вкладок)

### 1. **Регион и режим расчёта** 
🗺️ `mdi-map-marker`

**Назначение:** Установка глобальных географических параметров.

**Элементы управления:**
- **Регион по умолчанию** (v-select)
  - Выпадающий список со всеми регионами
  - Clearable (можно очистить выделение)
  - Используется для расчета ставок по профилям

- **Режим расчёта по площади** (v-switch)
  - Булева опция (вкл/выкл)
  - Влияет на таблицу материалов и итоговую стоимость

**Подсказка:** "Используются при создании новых проектов"

---

### 2. **Общие коэффициенты**
⚙️ `mdi-tune`

**Назначение:** Управление универсальными множителями для расчётов.

**Элементы управления:**
- **Коэффициент отходов (общий)** (v-text-field, number)
  - Min: 0
  - Step: 0.01
  - Умолчание: 1.0 (без изменения)

- **Коэффициент ремонтопригодности** (v-text-field, number)
  - Min: 0
  - Step: 0.01
  - Умолчание: 1.0 (без изменения)

**Подсказка:** "Применяются к новым проектам, если клиент явно не передал значения"

**Описание на странице:**  
Эти коэффициенты используются как базовые множители при расчете стоимости. Если клиент при создании проекта не указывает свои значения, применяются данные коэффициенты.

---

### 3. **Материалы по умолчанию**
📦 `mdi-package-variant`

**Назначение:** Выбор материалов, которые подставляются при добавлении новых позиций в проекты.

**Элементы управления:**
- **Листовой материал по умолчанию** (v-select)
  - Фильтрованный список материалов типа `plate`
  - Clearable
  - Используется при добавлении новых позиций в табель материалов

- **Кромочный материал по умолчанию** (v-select)
  - Фильтрованный список материалов типа `edge`
  - Clearable
  - Подставляется для кромки при расширении позиций

**Подсказка:** "Будут подставляться в новые проекты"

---

### 4. **Отходы (Коэффициенты отходов)**
♻️ `mdi-recycle`

**Назначение:** Детальная настройка коэффициентов отходов по категориям материалов.

**Структура:**
Три основные категории, каждая имеет одинаковый набор элементов управления:

#### 4.1 Плитные материалы
- **Коэффициент отходов** (v-text-field, number)
  - Min: 1
  - Step: 0.01
  - Placeholder: "1.00"
  
- **Применять** (v-switch, boolean)
  - Булева переменная `apply_waste_to_plate`
  - Включает/отключает применение коэффициента
  - Зелёный цвет (primary)

- **В отчёте** (v-switch, boolean)
  - Булева переменная `show_waste_plate_description`
  - Отключена если нет описания
  - Показывает/скрывает описание в финальном отчёте

- **Кнопка редактирования** 
  - Открывает диалоговое окно `showPlateDescDialog`
  - Позволяет добавить/отредактировать название и описание

#### 4.2 Кромка
Аналогичная структура для `waste_edge_coefficient`

#### 4.3 Операции
Аналогичная структура для `waste_operations_coefficient`

**Диалоговые окна для описаний:**
- v-dialog с max-width: 500px
- Содержит два поля:
  - **Заголовок** — название коэффициента/категории
  - **Текст описания** — многострочное текстовое поле (rows="6")
- Кнопки: "Закрыть" и "Сохранить"

**Подсказка:** "Специфичные коэффициенты для каждого типа материала"

---

### 5. **Справочные блоки**
📝 `mdi-text-box-outline`

**Назначение:** Создание и управление кастомными текстовых блоков, которые добавляются в отчёты проектов.

**Элементы управления:**
- **Список блоков** (динамический)
  - Каждый блок имеет:
    - **Заголовок** (v-text-field)
    - **Текст** (v-textarea)
    - **Чекбокс "Включить"** (v-checkbox) — включаемость блока
    - **Кнопка удаления** (v-btn, icon)

- **Кнопка добавления** 
  - Добавляет новый пустой блок в массив `text_blocks`
  - Структура: `{ title: '', text: '', enabled: true }`

**Логика:**
- При сохранении отправляются только включённые блоки (`enabled: true`)
- Пустые блоки исключаются из сохранения
- Блоки отображаются в финальном отчёте проекта

**Подсказка:** "Будут добавлены в отчёты ваших проектов"

---

### 6. **Безопасность**
🔒 `mdi-shield-lock`

**Назначение:** Управление безопасностью аккаунта и сессиями.

**Компоненты (вложенные):**
- `UserSecurityPanel` — панель управления безопасностью
- `UserDevicesPanel` — список доверенных устройств

**Функциональность:**
- Просмотр активных сессий
- Управление доверенными устройствами
- Просмотр истории входов
- Управление ключами доступа (API tokens)

## Правая панель — Contрольный элемент и контент

### Структура
```
settings-content
  ├─ settings-content-scroll (overflow-y: auto)
  │  └─ section-content (active)
  │     ├─ section-title
  │     ├─ section-hint
  │     └─ Специфичные элементы управления
  └─ settings-content-footer (sticky bottom)
     ├─ Уведомление об изменениях
     └─ Кнопки действий (Отменить, Сохранить)
```

### Состояния контента

**Состояние загрузки:** `loading.value`
- Отображается `v-skeleton-loader` с типом `"article, paragraph, paragraph, paragraph"`
- Блокирует взаимодействие с формой

**Состояние сохранения:** `saving.value`
- Блокирует кнопку сохранения
- Показывает progress/loading индикатор

**Состояние "грязной" формы:** `isDirty`
- Сравнивает текущее состояние с сохранённым
- Позволяет отменить изменения
- Активирует кнопку сохранения только при наличии изменений

## API взаимодействие

### Endpoints

**GET `/api/materials`** — получить все материалы
```
Response: Material[]
```

**GET `/api/regions`** — получить регионы
```
Response: { data: Region[] }
```

**GET `/api/user/settings`** — загрузить текущие настройки пользователя
```
Response: UserSettings
```

**PUT `/api/user/settings`** — сохранить изменения
```
Request: Partial<UserSettings>
Response: UserSettings
```

## Пользовательский опыт (UX)

### Навигация
- **Кликабельные пункты меню** — активная вкладка подсвечивается (v-list-item с :value binding)
- **Иконки + текст** — быстрое визуальное опознание раздела
- **Одновременный показ** — левая панель всегда видна, изменяется только правая

### Сохранение данных
1. Пользователь заполняет/изменяет поля
2. Система отслеживает изменения (isDirty)
3. При нажатии "Сохранить" отправляется PUT-запрос
4. На успех: зелёное уведомление + отверждение данных
5. На ошибку: красное уведомление с текстом ошибки

### Валидация
- **Минимум значения** — for коэффициентов устанавливается min="1" или min="0"
- **Шаг значения** — step="0.01" для точности до сотых
- **Обязательные поля** — region_id важен но опционален (clearable)

### Отмена изменений
- Кнопка "Отменить" восстанавливает оригинальное состояние
- Работает через сравнение `original.value` с текущим состоянием

## Ошибки и граничные случаи

1. **Отсутствие материалов** — пустой список в селектах
2. **Отсутствие регионов** — предупреждение в интерфейсе
3. **Сбой при загрузке** — отображение ошибки в snackbar
4. **Потеря интернета** — spinner блокирует форму до восстановления
5. **Параллельное редактирование** — последняя операция побеждает (нет оптимистичных обновлений)

## Примечания для разработчика

1. **Трёхуровневая сериализация описаний:**
   - UI-уровень: отдельные ref (`plateDesc.value`)
   - Form-уровень: встроены в `form.value.waste_plate_description`
   - Payload: конвертируются через `buildPayload()`

2. **Ленивая загрузка:**
   - Материалы и регионы загружаются параллельно через Promise.all()
   - UserSettings приходит последней после инициализации

3. **Dirty-tracking:**
   - Использует `JSON.stringify()` для глубокого сравнения
   - Включает все вложенные объекты

4. **Альтернативно для больших форм:**
   - Можно использовать библиотеку типа `vee-validate` для более мощной валидации
